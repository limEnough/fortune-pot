# 포춘팟 (FortunePot)

"사주로 보는 오늘의 운세" 모바일웹 — Next.js(App Router) + TypeScript + Tailwind + Zustand.

> **비회원(게스트) 전용 앱**입니다. 사주 정보는 브라우저(localStorage)에 저장됩니다.
> 예외는 [귀인지도](#귀인지도) 하나 — 여럿이 같은 지도를 채우는 기능이라 서버(KV)에 둡니다.

## 빠른 시작

```bash
npm install
npm run dev        # http://localhost:3000
```

로컬에서는 환경변수 없이 바로 실행됩니다. 귀인지도는 KV 대신 `.data/kv.json`
파일로 흉내 냅니다(`src/lib/kv.ts`). 운영 배포에는 KV 연결이 필요합니다 —
[배포](#배포-vercel) 참고.

## 폰트

Jua(제목)와 Noto Sans KR(본문)을 **repo 안에 직접 들고 있습니다.**

- `public/fonts/` — woff2 211개, 3.9 MB
- `src/app/fonts.css` — `@font-face` 337개 (자동 생성, 직접 고치지 마세요)

빌드할 때 바깥으로 나가지 않으므로, 어느 망에서 clone 하든 똑같이 빌드됩니다.
예전엔 `next/font` 로 빌드 타임에 Google Fonts 를 받아왔는데, TLS 를 가로채는
사내망에서 Node 가 인증서 체인을 거부해 폰트 없이 빌드되는 일이 있었습니다.
`next build` 는 에러로 멈추지만 `next dev` 는 **경고만 내고 Arial 폴백으로
조용히 넘어가서**, 화면은 뜨는데 글꼴만 어긋난 채로 한참 갑니다.

3.9 MB 를 다 받는 사람은 없습니다. `unicode-range` 로 쪼개져 있어서 브라우저가
화면에 실제로 뜬 글자가 속한 슬라이스만 가져갑니다. 사용자 이름이 두 폰트 모두에
렌더되기 때문에(`.f-name` 등) 한글 커버리지를 미리 줄일 수는 없어서, 통짜 파일
하나로 합치면 안 됩니다.

Noto 는 가변 폰트라 400 과 700 이 같은 woff2 를 가리킵니다. 중복이 아니라
`wght` 축으로 인스턴스를 고르는 것입니다.

### 폰트 갱신

새 버전을 받아야 할 때만 하면 됩니다. 이 단계에서만 네트워크(사내망이면
`NODE_EXTRA_CA_CERTS` 로 사내 루트 CA 지정)가 필요합니다.

1. [`src/app/layout.tsx`](src/app/layout.tsx) 를 잠시 `next/font/google` 방식으로 되돌립니다
   (`git log -- src/app/layout.tsx` 에 이전 형태가 있습니다)
2. `rm -rf .next && npm run build` — `next dev` 가 떠 있으면 `.next\trace` 를
   잡고 있어 `EPERM` 으로 죽으니 먼저 내리세요
3. `node scripts/vendor-fonts.js` — `public/fonts/` 와 `src/app/fonts.css` 재생성
4. `layout.tsx` 를 되돌린 것 원복 (`fonts.css` import 만 남기기)
5. `rm -rf .next && npm run build` 로 확인 — 이번엔 **CA 설정 없이** 통과해야 정상입니다

## 사용 흐름

### 최근 정보 이어쓰기

저장된 사주가 있으면 메인에서 **다른 화면으로 떠나기 전에** 정중앙 팝업으로 한 번
묻습니다. 예전엔 입력 폼 위 말풍선으로 제안했는데, 그건 이미 폼까지 들어간 사람만
보게 되어 "또 입력해야 하나" 하고 되돌아 나가는 사람에게는 닿지 않았습니다.

*네*를 누르면 이번 세션 동안 운세·사주·귀인지도가 모두 그 정보로 열립니다
(입력 폼을 건너뜁니다). 그 뒤 메인에는 _◯◯님 정보로 이용중이에요_ 안내와
**초기화** 버튼이 뜹니다. 초기화는 사주·지도 주소록·세션 상태를 함께 비웁니다.

| 무엇                           | 어디                                    | 왜                                                                                                 |
| ------------------------------ | --------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 사주 정보(이름·생일·시각·성별) | `localStorage` (`fortunepot-guest`)     | 다음 주에 다시 와도 남아 있어야 재방문할 이유가 됩니다                                             |
| "이 정보로 이용" 확인          | `sessionStorage` (`fortunepot-session`) | 탭을 새로 열면 한 번 더 묻는 편이, 친구 사주를 보러 왔는데 계속 내 정보로 조회되는 것보다 낫습니다 |

### 귀인지도에서 들어온 사람

귀인지도만 하고 나간 사람이 메인에 오면 아무것도 없는 새 방문자로 보였습니다.
방금 이름·생일을 다 넣었는데 운세를 보려면 처음부터 다시 넣어야 했습니다.
지금은 지도를 만들거나 이름을 올리는 순간 그 값을 사주 자리에 옮겨 심고
(`lib/map/plant.ts`), 이번 세션을 확인된 것으로 칩니다 — 자기가 방금 넣은 값을
다시 물어볼 이유가 없으니 메인 팝업도 뜨지 않고 바로 _이용중_ 상태가 됩니다.
**이미 저장된 사주가 있으면 건드리지 않습니다**(남의 지도에 이름을 올렸다고 내
사주가 바뀌면 안 되니까요).

지도는 성별을 받지 않고 시각도 *모르겠어요*가 기본이라, 이렇게 심긴 사주는
칸이 비어 있습니다. 운세·사주 화면은 성별을 표시에 쓰고 시주가 있고 없고가 풀이를
크게 바꾸므로, 그쪽으로 갈 때 입력 폼을 한 번 거칩니다. 폼은 **나머지 칸이 채워진
채로** 뜨고 빈 칸에 _확인 필요_ 표시가 붙습니다. 시각은 그래도 모르면
_모르겠어요_ 그대로 두면 됩니다.

`isComplete()`(`types/saju.ts`)가 그 판정을 한 곳에서 합니다. 메인의 진입 버튼과
`/fortune`·`/saju` 가 모두 이 함수를 보고 폼으로 우회시킵니다.

### 입구

시작 화면에서 **먼저 볼 화면을 고르는 것**으로 출발합니다. 운세만 궁금한 사람과
사주 풀이가 궁금한 사람의 목적지가 다르기 때문에, 입구를 두 개로 두었습니다.

```
             ┌ 🔮 오늘의 운세 → /infoinput?next=fortune ┐
시작 화면 ───┤                                           ├─→ 사주 입력 폼 ─→ 고른 화면
             └ 📜 나의 사주   → /infoinput?next=saju    ┘      (공통)
```

- 어느 쪽을 눌러도 **입력 폼은 같습니다**(이름·생년월일·시각·성별). 분석 후 도착지만 달라져요.
- 도착지는 쿼리 파라미터 `?next=fortune|saju` 하나로만 전달되고 `SajuForm`이 읽어서 이동합니다.
  파라미터가 없으면 기본값은 `/fortune` 입니다.
  `useSearchParams()` 프리렌더 요건 때문에 폼은 `<Suspense>`로 감싸져 있습니다.
- 최근 조회 기록이 있으면 폼 상단 말풍선이 재사용을 제안하고, 이때도 고른 도착지로 갑니다.

### 입력 화면이 둘인 이유

같은 폼이지만 **들어온 이유가 다르면 버튼이 할 일도 다릅니다.**

| 라우트 | 언제 | 버튼 | 말풍선 |
|---|---|---|---|
| `/infoinput?next=` | 운세·사주를 보러 가는 길목 | 저장 후 **고른 화면으로 이동** | 뜸(지름길) |
| `/info?from=` | 메뉴에서 내 정보를 고치러 | **저장하고 있던 자리로 복귀** | 안 뜸 |

예전엔 `/onboarding` 하나가 둘을 겸했습니다. 그래서 정보를 고치러 들어와도 맨 위에
*"최근 조회한 ◯◯님으로 오늘의 운세를 확인해보시겠어요?"* 가 떴습니다 — 고치러 온
사람에게 고치지 말라고 권하는 셈이었죠. 화면을 나누니 말풍선 조건도 라우트가
결정하게 되어 단순해졌습니다.

`/onboarding` 은 `/infoinput` 으로 넘겨주기만 합니다(예전 링크·북마크 보호).

도착한 뒤에는 두 화면이 상단 칩으로 서로를 오갑니다.

| 화면       | 칩                      | 동작                                                     |
| ---------- | ----------------------- | -------------------------------------------------------- |
| `/fortune` | 📋 내 사주 정보         | 입력값 확인 바텀시트 → 전체 풀이 또는 정보 수정으로 이동 |
| `/saju`    | 🔮 오늘의 운세 확인하기 | `/fortune` 으로 바로 이동                                |

LNB의 _내 정보 수정하기_ 는 `/info?from=` 으로 가고, 저장하면 들어올 때 보던 화면으로
돌려보냅니다.

LNB에는 **세 화면이 늘 다 보입니다**(운세·사주·귀인지도). 예전엔 사주가 없으면
운세·사주 항목을 아예 숨겼는데, 그러면 귀인지도만 하고 온 사람의 메뉴에 귀인지도
하나만 남아 다른 곳으로 갈 길이 없었습니다. 지금은 늘 띄우고 정보가 모자라면 입력
폼을 거쳐 돌아오게 합니다. 지금 보고 있는 화면은 _지금 화면_ 표시로 남깁니다.
귀인지도 화면들(`/map`, `/map/[id]`, `/map/[id]/view`)도 다른 화면과 같은 헤더를
씁니다.

## 귀인지도

혼자 보는 다른 화면과 달리 **여럿이 한 장을 채우는** 화면입니다.

```
나  ─ 정보 입력 → 지도 생성(id + 열쇠) → 링크 공유
                                            │
친구 ─ 링크 열기 → 자기 정보 입력 → 내가 그 사람에게 어떤 사람인지 즉시 확인
                                            ├→ 주인 지도 구경 (읽기 전용)
                                            └→ 내 지도에 별로 추가
```

메인에서 최근 정보를 이어쓰기로 했다면 입력 폼 대신 _◯◯님으로 지도 만들기_ 버튼
하나만 나옵니다. 지도를 만드는 건 서버에 자리를 만들고 공유 링크가 생기는 일이라
버튼 한 번은 남겨둡니다.

### 유형과 점수

기준은 두 사람의 **일간 오행 관계** 하나입니다. 상생·상극 순환에서 상대가 내 어느
자리에 서 있느냐가 곧 유형이고, 유형 다섯이 오행 다섯과 1:1 이라 지도를 다섯 구역으로
나눌 수 있습니다.

| 유형           | 관계             | 예(내가 토) |
| -------------- | ---------------- | ----------- |
| 🌟 귀인        | 상대가 나를 생함 | 화생토      |
| 🤝 단짝        | 같은 오행        | 토토        |
| 🌱 내 사람     | 내가 상대를 생함 | 토생금      |
| 🧭 오른팔      | 내가 상대를 극함 | 토극수      |
| ⚡ 호랑이 선생 | 상대가 나를 극함 | 목극토      |

케미(32~99)는 유형별 기본값에 연·월·일지의 합충(육합·삼합·충·해)과 오행 보완,
음양 조화를 더해 조정합니다. **난수를 쓰지 않으므로** 같은 두 사람은 언제 봐도
같은 숫자가 나옵니다. 별지도에서는 유형이 각도, 케미가 거리·밝기·크기가 됩니다.

태어난 시간은 **양쪽 다 알 때만** 시지 합충을 더하고(가중치 0.3), 오행 집계도
여섯 글자에서 여덟 글자로 늘어납니다. 모르면 그 항목만 빠질 뿐 결과는 나옵니다.
성별은 **받지 않습니다** — 궁합이 일간 오행과 지지 합충으로 나오므로 쓸 데가 없고,
남의 링크에서 채우는 칸은 적을수록 좋습니다.

### 같은 사람은 한 줄

사람이 링크를 다시 여는 이유는 대개 **고쳐 넣으려는 것**입니다(이름 표기 변경,
생일 오타, 양/음력 토글). 그래서 신원을 입력값으로 잡으면 고칠 때마다 다른 사람이
되어 줄이 쌓입니다. 신원 기준을 입력과 분리해 두 겹으로 둡니다.

| 기준 | 무엇                                                        | 언제                                    |
| ---- | ----------------------------------------------------------- | --------------------------------------- |
| 1차  | 방문자 토큰 (`fortunepot-visitor`, 브라우저에 심는 임의 id) | 같은 브라우저면 무엇을 고쳐도 같은 사람 |
| 2차  | 정규화한 이름 + 양력 생일 (공백 제거·소문자·NFC)            | 기기가 바뀌어 토큰이 없을 때            |

둘 중 하나라도 걸리면 기존 줄을 **최신 내용으로 바꾸고** 흩어진 줄은 걷어냅니다.
처음 올린 시각(`at`)은 지킵니다 — 고쳐 올렸다고 새로 온 사람이 되는 건 아니니까요.
2차 기준은 저장해 둔 값이 아니라 그때그때 계산하므로, 이 방식 이전에 쌓인 줄도
같은 규칙으로 흡수됩니다.

IP·기기 지문은 쓰지 않습니다. 공용 와이파이에서 **남의 줄을 덮어쓰는** 실패가
중복보다 나쁩니다. 같은 이유로 생일만으로는 합치지 않습니다(같은 날 태어난 두 친구).

남는 한계는 **다른 기기에서 이름과 생일을 둘 다 바꿔** 올리는 경우입니다. 공유할 수
있는 신원이 하나도 없으므로 새 줄이 되고, 주인이 *지우기*로 정리합니다.

### 저장과 프라이버시

지도는 KV 에 두 키로 나눠 둡니다. 합류를 해시 필드 쓰기로 처리해, 링크를 여러 명이
동시에 열어도 서로의 글을 덮어쓰지 않습니다.

```
map:{id}    주인 문서 (이름·생일·양력 환산·열쇠)
map:{id}:e  합류자 해시 (필드 = 이름+생일 해시라 같은 사람이 두 번 넣어도 한 줄)
```

- **생년월일은 서버 밖으로 나가지 않습니다.** 궁합 계산이 라우트 핸들러에서 끝나고
  브라우저로는 이름·유형·점수·문구만 내려갑니다. 링크를 주운 사람이 주인 생일을
  알아낼 방법이 없어야 하기 때문입니다.
- 링크(`/map/{id}`)만으로 보이는 건 **주인 이름과 인원수**까지입니다. 지도를 펼쳐
  보려면 둘 중 하나여야 합니다.

  | 누구             | 무엇으로                                   | 무엇을                             |
  | ---------------- | ------------------------------------------ | ---------------------------------- |
  | 주인             | 열쇠(`key`, localStorage `fortunepot-map`) | 전체 + 지우기                      |
  | 이름을 올린 사람 | 방문자 토큰                                | 전체, 읽기 전용 (`/map/{id}/view`) |

  링크만 주운 사람은 열리지 않습니다 — 참여자 명단이 단톡방에 그대로 퍼지는 걸
  막으면서, 이름을 올린 사람에게는 "내가 이 사람들 사이 어디쯤인지"를 돌려줍니다.
  주인 화면의 공유 카드에도 *이름을 올린 사람은 이 지도를 볼 수 있어요*라고
  적어 둡니다. 열쇠는 비회원 앱이라 잃으면 되찾을 방법이 없습니다.

- 보관 기간은 마지막 쓰기로부터 200일, 한 지도에 60명까지입니다.

### 입력

이름, 생년월일 여섯 자리(`930821`), 양/음력, 태어난 시간을 받습니다.
생년월일을 캘린더가 아니라 숫자 여섯 자리로 받는 건 **남의 링크에서 채우는 칸**이라
한 칸에 두드리고 끝나는 쪽이 이탈이 적기 때문입니다. 시간은 모르는 사람이 많아
**모르겠어요가 기본값**이고, 없어도 결과는 나옵니다. 음력은 `lunarToSolar` 로
양력에 옮겨 계산합니다(윤달 미지원).

## 카드 이미지 저장

두 화면 맨 아래 버튼이 각각 카드를 그려 미리보기 바텀시트로 띄웁니다.

| 화면       | 카드           | 담기는 것                                        |
| ---------- | -------------- | ------------------------------------------------ |
| `/saju`    | 사주 정보 카드 | 명식·오행·십성·일간 풀이 — **바뀌지 않는 것**    |
| `/fortune` | 오늘의 부적    | 그날의 등급·분야별 운세·행운·한마디 — **오늘치** |

**DOM 스냅샷(html2canvas 류)을 쓰지 않고 Canvas 2D 로 직접 그립니다.** 화면이
gradient·backdrop-filter·box-shadow 로 짜여 있어 스냅샷 계열이 그대로 옮기지
못하고, 접힘 패널·스크롤 위치 같은 화면 상태에 결과가 끌려다닙니다. 게다가
카드는 화면과 레이아웃이 아예 다릅니다(세로로 길고 여백이 넉넉한 인쇄물).

- 좌표계는 **가로 1080px 고정**, 세로는 내용에 따라. 높이를 미리 알 수 없으므로
  투명 레이어에 내용을 먼저 그려 실제 높이를 재고, 그 높이로 만든 캔버스에
  배경 → 레이어 순으로 합성합니다(`draw.ts` 의 `layered`).
- 그리기 전에 **`document.fonts.load(font, text)` 로 글리프를 받아둡니다.**
  `fonts.css` 가 `unicode-range` 로 쪼개져 있어서, 화면에 아직 안 뜬 글자는
  슬라이스가 없습니다. 그대로 그리면 폴백으로 그려질 뿐 아니라 `measureText` 도
  폴백 기준이라 **줄바꿈까지 어긋납니다.**
- 줄바꿈은 CSS `word-break: keep-all` 과 같은 규칙입니다. 브라우저 기본값은
  한글을 음절 단위로 끊는데(UAX #14), 줄이 긴 카드에선 끝의 한두 글자만
  넘어가는 모양이 자주 나옵니다.
- 저장 경로가 셋입니다 — 공유 시트(`navigator.share`), `a[download]`,
  미리보기 이미지 길게 누르기. iOS 에서 앞의 둘이 막혀도 마지막은 늘 통하므로
  미리보기를 반드시 보여줍니다.
- 캐릭터 SVG 는 `data:` URL 로 넣어 캔버스가 오염되지 않게 합니다(`toBlob` 가능).
  브라우저가 SVG 를 고유 크기로 래스터화한 뒤 확대하는 경우가 있어, 그릴 크기를
  `width`/`height` 속성에 미리 박아 넣습니다.

## 데이터 전략

- **계산 로직**(명식·십성·세운·궁합) → 코드(`lib/saju`). 저장하지 않음.
- **사용자 입력**(생년월일시) → Zustand persist(localStorage)에 보관.
- **오늘의 운세** → 이름+날짜 seed로 매번 계산(저장 안 함).
- **귀인지도만 예외** → KV. 여러 사람이 같은 지도를 채우므로 브라우저에 둘 수 없음.
  브라우저에 남는 건 지도 id·열쇠뿐.
- 해설 문구는 `lib/saju/text.ts`. 자주 바꾸거나 다국어가 필요해지면 DB/CMS로 이전.

## 릴리즈 노트

이력은 두 군데에 있고, **버전 문자열을 반드시 맞춰야** 합니다.

| 위치                                         | 대상      | 문체                                                   |
| -------------------------------------------- | --------- | ------------------------------------------------------ |
| [`CHANGELOG.md`](CHANGELOG.md)               | 개발자    | Keep a Changelog (`Added`/`Changed`/`Fixed`/`Removed`) |
| [`src/lib/releases.ts`](src/lib/releases.ts) | 앱 사용자 | "~했어요" 안내 문장                                    |

앱에서는 헤더 **확성기 버튼**으로 보여줍니다. `seenVersion`(localStorage `fortunepot-release`)이
`RELEASES[0].version`과 다르면 6초짜리 말풍선 + 점이 뜨고, 시트를 열면 확인 처리됩니다.
말풍선 노출 시간은 `TopBar.tsx`의 `BUBBLE_MS` 상수입니다.
첫 방문자에겐 알리지 않고 방문 시점 버전을 기준점으로 심어, **다음** 릴리즈부터 뜹니다.

`package.json`의 `version`은 **마지막으로 태그된** 릴리즈를 가리킵니다.
개발 중에는 `RELEASES[0].version`(다음 릴리즈)보다 한 단계 뒤에 있는 게 정상입니다.

### 새 버전 배포 절차

```bash
# 1. CHANGELOG.md 의 [Unreleased] → [x.y.z] 로 확정, 비교 링크 갱신
# 2. src/lib/releases.ts 배열 맨 앞에 사용자 문장으로 추가
# 3. package.json version 동기화
npm version 0.5.0 -m "chore: [release] v%s"   # 커밋 + v0.5.0 태그
git push --follow-tags

# 4. GitHub Release 발행
gh release create v0.5.0 --title "v0.5.0 — 한 줄 요약" --notes "$(...)"
```

GitHub 저장소 우측 **Releases** 에 태그별 카드로 쌓이고, 소스 아카이브가 자동 첨부됩니다.
웹 UI의 _Draft a new release → Generate release notes_ 를 쓰면 머지된 PR 제목으로 초안이 생성됩니다.

## ⚠️ 사주 계산 주의

명식·세운 계산은 [`lunar-javascript`](https://github.com/6tail/lunar-javascript) 만세력을 사용하며(입춘·각월 절입 시각, 23시 자시 경계 반영), 한국 표준시 입력을 **서울 경도 기준 진태양시(균시차 포함)**로 환산해 명식을 산출합니다.
출생지 경도가 서울과 크게 다르거나 시지 경계 부근이면 별도 보정이 필요할 수 있습니다.

## 배포 (Vercel)

Vercel 프로젝트로 import 후 배포합니다. 귀인지도를 쓰려면 KV 를 하나 붙여야 합니다.

1. 프로젝트 → **Storage → Create Database → Upstash Redis**(구 Vercel KV) 연결
2. 연결하면 `KV_REST_API_URL` · `KV_REST_API_TOKEN` 이 자동으로 주입됩니다
   (`UPSTASH_REDIS_REST_URL` · `UPSTASH_REDIS_REST_TOKEN` 이름도 그대로 받습니다)
3. 재배포

KV 를 붙이지 않아도 나머지 화면(운세·사주·카드 저장)은 그대로 동작합니다.
귀인지도만 "지도 보관소에 연결하지 못했어요" 안내를 내고, 서버 로그에 원인을 남깁니다.
**운영에서는 파일 폴백으로 흐르지 않습니다** — 서버리스 파일시스템은 요청마다 날아가서
저장된 것처럼 보이다가 사라지는 게 제일 나쁘기 때문입니다.
